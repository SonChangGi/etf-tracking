소스 상태

계산 방법과 한계가격 효과, 잔차 신호, 커버리지와 히스토리 범위

Methodology

계산 방법과 한계

가격 효과

전일 전체 보유종목 비중에 개별 종목의 KRW 평가단가 수익률을 적용하고, 전체 보유종목 가중 평균 수익률로 정규화한 no-trade 예측 비중을 계산합니다.

잔차 신호

실제 비중 변화와 예측 비중 변화의 차이를 기존 Python 분류값으로 표시합니다. 실제 주문 확정이 아닌 no-trade 기준 대비 가능성 신호입니다.

커버리지

수익률이 확보된 전일 전체 보유종목 비중 합계가 낮으면 가격·매매 요인을 단정하지 않고 낮은 신뢰도 상태를 유지합니다.

히스토리 범위

커밋된 상장일 백필과 missing-only 갱신 범위를 사용합니다. 더 과거 분석은 검토된 수동 백필로만 확장합니다.

데이터 업데이트 상세GitHub Actions 수동 실행과 CLI 명령

Manual Update

없는 날짜만 채우는 수동 업데이트

수동 워크플로는 저장된 usable 스냅샷을 다시 요청하지 않고, 최신 기준일과 선택한 백필 범위에서 아직 없는 날짜만 채웁니다.

  • 자동 스케줄공급자 공개 시차를 고려한 예약 실행 상태는 Actions에서 확인합니다.
  • 수동 실행backfill_start_date로 누락 구간을 채우고, 필요할 때만 refresh_existing을 사용합니다.
GitHub Actions에서 수동 업데이트 열기 워크플로 상태 보기 gh workflow run update-data.yml --repo SonChangGi/etf-tracking --ref main -f backfill_all=false -f backfill_start_date= -f refresh_existing=false -f strict_validation=true 기본값은 missing-only입니다.
연구용 정적 스냅샷 · 잔차 신호는 실제 운용사 주문 확정이나 투자·매매 조언이 아닙니다.
